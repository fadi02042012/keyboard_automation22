# Keyboard Automation AI

تطبيق سطح مكتب مبني باستخدام Flutter وWindows Runner لأتمتة إدخال لوحة المفاتيح والفأرة عبر سيناريوهات قابلة للحفظ والاستيراد والتصدير. صُمّم المشروع ليكون واضحاً للمستخدم، قابلاً للصيانة، ومتوافقاً مع النصوص العربية وUnicode.

## الوظائف الرئيسية

يسمح التطبيق بإنشاء خطوات من نوع النص، المفتاح مع المعدلات، التأخير، النقر بالفأرة، العدادات، وتنتظر النافذة المستهدفة قبل التنفيذ. كما يدعم تكرار الخطوات أو نطاق منها، التكرار الدوري للسيناريو، المتغيرات الزمنية، العدادات، الحافظة، واختيار النافذة المستهدفة.

يتم حفظ السيناريوهات محلياً، بينما يستخدم التصدير صيغة JSON موثقة تحتوي على `schemaVersion` واسم السيناريو وتاريخ التصدير. ويظل الاستيراد متوافقاً مع الصيغة القديمة التي كانت عبارة عن قائمة مباشرة من الخطوات.

## المتطلبات

يحتاج المشروع إلى Flutter مستقر يدعم Dart SDK 3.7 أو أحدث، وإلى بيئة Windows قادرة على بناء C++17. كما يجب تشغيل التطبيق في جلسة Windows تسمح بتفعيل النوافذ المستهدفة وإرسال إدخال النظام؛ وقد تمنع سياسات Windows أو التطبيقات ذات الصلاحيات الأعلى إرسال الإدخال إليها.

## التشغيل محلياً

من مجلد المشروع نفّذ الأوامر التالية:

```powershell
flutter pub get
flutter analyze
flutter test
flutter run -d windows
```

يمكن أيضاً تشغيل `Run.bat` من Windows. أصبح الملف يعتمد على مساره الحالي بدلاً من مسار ثابت، ويتحقق من وجود Flutter، ثم يجلب الاعتمادات ويشغّل التحليل والبرنامج.

## البناء والتوزيع

لبناء نسخة Windows قابلة للتوزيع استخدم:

```powershell
flutter build windows --release
```

توجد الملفات الناتجة عادةً ضمن `build/windows/x64/runner/Release/`. يجب توزيع مجلد الإصدار كاملاً، وليس الملف التنفيذي وحده، لأن Flutter يعتمد على ملفات DLL وبيانات مرافقة.

## البنية التقنية

| الطبقة | المسؤولية |
|---|---|
| `lib/main.dart` | نموذج الخطوات والسيناريوهات، الواجهة، التخزين، الاستيراد والتصدير، وتنفيذ السيناريو |
| `windows/runner/automation_engine.*` | قناة MethodChannel والتحقق من المعاملات وربط Flutter بواجهات Windows |
| `windows/runner/keyboard_input.*` | إدخال النصوص وUnicode والمفاتيح والمعدلات عبر `SendInput` |
| `windows/runner/mouse_input.*` | تحريك المؤشر والنقر الأحادي والمزدوج مع التحقق من النتيجة |
| `windows/runner/window_manager.*` | اكتشاف النوافذ وقراءة العناوين العربية باستخدام Unicode |
| `test/automation_model_test.dart` | اختبارات التوافق مع JSON والتطبيع الآمن للبيانات |

> مبدأ مهم: لا تُرسل أي خطوة إدخال قبل التحقق من النافذة المستهدفة، ولا يستمر التنفيذ بصمت بعد فشل إدخال أصلي.

## ملاحظات الأمان والاعتمادية

إرسال إدخال النظام وظيفة حساسة؛ لذلك ينبغي تشغيل السيناريوهات على خطوات معروفة ومراجعة الإحداثيات والنافذة قبل البدء. تم تحديد حدود للتكرار والتأخير والمهلة والإحداثيات عند فك JSON، كما يتم رفض المعدلات أو أزرار الفأرة غير المعروفة بدلاً من تجاهلها.

تُستخدم أوامر PowerShell بوسائط منفصلة و`-NoProfile` و`-NonInteractive`، مع تمرير النص المشفر Base64 لتقليل مشاكل الاقتباس مع العناوين العربية. لا يطلب التطبيق أو يخزن كلمات مرور أو رموز وصول.

## الاختبارات والتحقق

اختبارات Dart تغطي تحويل الخطوات ذهاباً وإياباً، قراءة الصيغة القديمة، تقليم القيم غير الآمنة، والحفاظ على الخطوات السليمة عند وجود خطوة تالفة. لا يمكن تنفيذ Flutter Analyzer أو الاختبارات داخل بيئة لا تحتوي على Flutter SDK؛ يجب تنفيذها على جهاز التطوير قبل الإصدار النهائي.

قبل إنشاء إصدار إنتاجي، يُنصح بتنفيذ `flutter analyze` و`flutter test` ثم تجربة سيناريو يتضمن نصاً عربياً، حافظة، مفتاحاً مع `CTRL`، نقراً مزدوجاً، وانتظار نافذة غير متاحة للتأكد من ظهور الخطأ والإيقاف الآمن.

## التغييرات الهندسية المهمة

تمت إضافة `dart:async` صراحةً لاستخدام `Timer` و`Completer`، وإصلاح اسم حزمة Dart المفقود، وإزالة الاعتمادات غير المستخدمة. كما تم نقل `window_manager.cpp` إلى قائمة مصادر CMake بدلاً من تضمينه داخل ملف مصدر آخر، وإضافة قناة أصلية للحافظة، وتقوية التحقق من أنواع معاملات MethodChannel، وتحسين إدخال Unicode وتجميع الأحداث في دفعات لتقليل تكلفة الاستدعاءات.

تم أيضاً توحيد إعادة المحاولة في Dart، وإلغاء الانتظارات عند الإيقاف أو إغلاق الصفحة، وتحويل رسائل الفشل الأصلية إلى أخطاء واضحة، وتحسين التوافق مع البيانات المحفوظة سابقاً.
